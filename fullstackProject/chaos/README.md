# Этап 24 — Хаос-тестирование (toxiproxy)

Юниты, интеграция, live-int, e2e и k8s доказывают, что контур работает,
когда всё работает. Хаос-этап доказывает обратное: что контур **выживает**,
когда сеть подведёт. Инструмент — [toxiproxy](https://github.com/Shopify/toxiproxy):
прозрачный TCP-прокси, чьё поведение ломают через HTTP API в рантайме.

## Устройство

Стенд — базовый `docker-compose.yml` плюс оверлей `docker-compose.chaos.yml`:

```
        ┌─ pg-api (15433) ────────► postgres:5432
api ────┤
        └─ amqp-api (15673) ─────► rabbitmq:5672

          ┌─ pg-relay (15434) ────► postgres:5432
relay ────┤
          └─ amqp-relay (15674) ─► rabbitmq:5672
```

Четыре прокси вместо двух — ради **изоляции сбоя**: сценарий «брокер
недоступен Курьеру» удаляет прокси `amqp-relay` и не трогает путь API
(`amqp-api`) и воркера (напрямую). Прокси регистрируются конфигом
`toxiproxy.json` при старте контейнера — к моменту подъёма api порты
уже слушаются, гонки «подключение раньше прокси» нет.

HTTP API toxiproxy выведен на `localhost:18475` — сценарии вносят
токсики в рантайме (`latency` в оба направления) или валят канал
целиком (удаление прокси: порт закрыт, живые соединения оборваны —
клиент видит честный обрыв TCP, а не молчаливый чёрный ящик).

Воркеру оверлей даёт `SUCCESS_RATE=1`: вердикты детерминированы —
предмет этапа сетевые сбои, а не платёжная лотерея (дефолт 0.9).

## Сценарии (`apps/api/test/*.chaos.spec.ts`)

| Спека | Сбой | Инварианты |
|---|---|---|
| `pg-latency` | латентность 400 мс до PG у API и Курьера | цикл брони проходит, хвост outbox разъезжается, письмо доходит |
| `broker-blackout` | RabbitMQ недоступен **только Курьеру** | брони проводят вердикты, 5 событий копятся в pending, failedAttempts растёт; после снятия — полный разъезд без потерь |
| `relay-db-blackout` | Postgres недоступен **только Курьеру** | витрина честно падает (500), после восстановления пул переподключается и разъезжает хвост |

Наблюдаемые точки:

- `GET localhost:18094/outbox` — витрина Курьера: `pending`,
  `publishedTotal`, `failedAttempts`;
- письмо `password_reset` в истории notification
  (`GET localhost:18082/notifications?bookingId=<email>`) — его
  единственный путь лежит через outbox → Курьер → брокер.
  `booking_confirmed` для этого не годится: вердикт публикует воркер
  напрямую, минуя outbox.

## Запуск

CI — джоба `chaos` воркфлоу `cinebooking` (стенд с оверлеем, спеки
`--runInBand`: сценарии делят один toxiproxy). Локально:

```bash
docker compose -f docker-compose.yml -f docker-compose.chaos.yml up --build --wait \
  postgres redis rabbitmq toxiproxy \
  worker notification recommendation reminder pricing ratelimiter analytics \
  outbox-relay api
npm run test:chaos        # из apps/api
```

Без стенда с оверлеем спеки тихо пропускаются с предупреждением —
обычный e2e-стенд для хаоса не годится (нет toxiproxy на 18475).

## Грабли этапа

- **Блэкаут ≠ `down` toxic.** Токсик `down` держит соединение открытым
  и молча не пропускает данные — клиент висит до собственного таймаута.
  Для «канала нет» прокси удаляется целиком: новые подключения —
  ECONNREFUSED, живые — обрыв. Ошибки мгновенные, поведение честное.
- **Что считать доставкой.** Витрина `/outbox` — первичный оракул
  (pending/published/failed), письмо сброса пароля — сквозное
  подтверждение; письмо брони оракулом быть не может (см. выше).
- **Ассерты с запасом на бэкофф.** Неудачная публикация отодвигает
  повтор бэкоффом 500 мс × 2ⁿ (кэп 60 с) — таймауты разъезда хвоста
  в сценариях щедрые (120–150 с), «снять сбой и ждать мгновенно»
  не работает.
