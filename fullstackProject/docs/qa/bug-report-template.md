# Шаблон баг-репорта

Заполняется на каждый дефект, найденный ручной проходкой или на стенде.
Автотестовые падения дублируются репортом, если причина не очевидна из
диффа. Пример заполнения — внизу.

## Шаблон

```markdown
### BUG-<номер>: <краткая суть одним предложением>

**Severity:** Blocker / Critical / Major / Minor / Trivial
**Priority:** P1 / P2 / P3
**Окружение:** docker-стенд | локальный гибрид | GitHub Pages-демо
**Ветка/коммит:** <ref>
**Компонент:** api / web / worker / infra
**Где найдено:** чек-лист CL-<N> | тест-кейс TC-<ID> | исследовательская сессия

**Предусловия**
- <что должно быть сделано до воспроизведения>

**Шаги воспроизведения**
1. …
2. …

**Фактический результат**
<что происходит>

**Ожидаемый результат**
<что должно происходить по требованиям/тест-кейсу>

**Воспроизводимость:** всегда (N из M прогонов) / при условиях …
**Вложения:** скриншот, лог, HAR, запись экрана

**Как чинить (гипотеза)**
- <если понятна область/причина>
```

## Severity-шкала проекта

| Уровень | Критерий | Пример |
|---|---|---|
| Blocker | Стенд не стартует или поток брони невозможен | API падает на POST /bookings |
| Critical | Данные портятся или теряются деньги | место продано дважды; возврат не освободил места |
| Major | Ключевая функция сломана, есть обход | SSE не переподключается после рестарта api |
| Minor | Некритичное расхождение | бейдж «из кэша» не обновился без F5 |
| Trivial | Косметика | опечатка в тексте бейджа |

## Пример заполнения

```markdown
### BUG-042: События SSE приходят пачкой с задержкой ~30 c через docker-nginx

Severity: Major
Priority: P2
Окружение: docker-стенд (web :18080)
Ветка/коммит: 32228df
Компонент: web (nginx.conf)
Где найдено: тест-кейс TC-SSE-004

Предусловия
- Стенд поднят: docker compose up --build
- Открыты две вкладки http://localhost:18080

Шаги воспроизведения
1. Вкладка A — страница «Мои брони», DevTools → Network → EventStream
2. Вкладка B — создать бронь на любое место

Фактический результат
Во вкладке A событие booking появляется через ~30 c сразу пачкой
из нескольких событий; в Network у запроса stream — «pending», размер
ответа растёт скачком.

Ожидаемый результат
Событие приходит за <1 c после мутации (proxy_buffering off — см. TC-SSE-004).

Воспроизводимость: всегда (3 из 3)
Вложения: скриншот EventStream с таймстампами

Как чинить (гипотеза)
- Проверить наличие `proxy_buffering off;` в блоке location /api/ —
  симптом характерен для буферизации прокси.
```
