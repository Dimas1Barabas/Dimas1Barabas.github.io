# Тест-кейсы: CineBooking

> **Где живут кейсы в индустрии.** Живой источник — этот md в репозитории
> (docs-as-code, ревью через PR). Снапшоты для передачи/импорта:
> [test-cases.txt](test-cases.txt) — читаемая «распечатка», как выгрузка из
> TMS; [test-cases.csv](test-cases.csv) — формат импорта в TestRail / Test IT /
> Allure TestOps (UTF-8 c BOM, открывается в Excel). В самих TMS кейсы
> хранятся в БД с прогонами и историей; Excel/Sheets — типичный вариант
> малых команд; Word — только формальные артефакты (ПМИ по ГОСТ 34).

Формат каждого кейса: идентификатор, приоритет, тип, привязка к автоматизации
(если кейс покрыт автотестом — ссылка на реальный файл в репозитории),
предусловия, шаги, ожидаемый результат, постусловия.

Приоритеты: **High** — блокирует релиз при падении; **Medium** — важная
функциональность, фикс в текущей итерации; **Low** — косметика/редкие ветки.
Типы: `функц.` / `негатив.` / `гранич.` / `конкур.` / `отказоуст.`.

Сводка: 230 кейсов, из них 218 покрыты автотестами (TC-SSE-003,
TC-OBX-008, TC-CNR-010 — частично), 12 — ручные (нужен стенд).

## Модуль «Security-заголовки (Helmet + nginx + cookie-флаги)»

## Модуль «Kubernetes (kind в CI)»

Стенд вторым оркестратором: те же приложения и инфраструктура из
kustomize-манифестов (`k8s/base` + overlay `ci`) поднимаются в одноразовом
kind-кластере на раннере, вход — Gateway API (Envoy Gateway, преемник
retired ingress-nginx), и полный e2e-сьют гоняется через шлюз — как против
compose-стенда, но транспорт кластерный: Gateway → web nginx → api.
Проверяет не «работает ли Kubernetes», а переносимость стенда: env 1:1,
порядок старта без depends_on, здоровье и долгие соединения (SSE/WS)
через новый вход.

## Модуль «Аналитика поведения»

Контур поведенческой статистики: веб-трекер копит события (страницы,
воронка брони, клики по местам, время в модалке) и батчами до 50 шлёт
в публичный инжест API — валидация + лимит Привратника на aid → брокер
`cinema ← analytics.event` → Go-сервис «Аналитик» складывает два потока
(поведение с веба + транзакционные брони) в агрегаты → витрина

Аналитик опционален для стенда: без него прокси отвечает `available:false`,
e2e-контур честно скипается (k8s-оверлей сервис не разворачивает).

## Модуль «Транзакционный outbox (outbox-relay, „Курьер")»

Гарантия доставки событий: бизнес-событие и бизнес-данные коммитятся
одной транзакцией Postgres (таблица `outbox_messages`), публикацией
владеет отдельный Go-сервис «Курьер» — батчи `FOR UPDATE SKIP LOCKED`,
бэкофф неудач, будильник gRPC `Notify` сразу после COMMIT. Доставка
at-least-once: дубли ределивери гасят консьюмеры по amqp messageId =
id записи. Через outbox идут все события API (бронь, вердикты, отмена,
waitlist, сброс пароля, сигналы КиноСоветнику); исключения осознанные —
`analytics.event` (без БД в контуре), SSE (после коммита, in-process),
напоминания (fire-and-forget gRPC).

## Модуль «Хаос-инжекция (toxiproxy, этап 24)»

Стенд с chaos-оверлеем (`docker-compose.chaos.yml`): между клиентами и
инфраструктурой стоит toxiproxy — четыре прокси (pg-api, pg-relay,
amqp-api, amqp-relay) позволяют валить канал ТОЧЕЧНО, у одного участника.
Сценарии вносят сбои в рантайме через HTTP API toxiproxy; воркер
детерминирован (SUCCESS_RATE=1 — вердикты не лотерея). Наблюдаемые точки:
витрина Курьера `/outbox` (pending, publishedTotal, failedAttempts) и
письмо `password_reset` в истории notification — единственный эффект,
который возможен строго через доставку outbox → Курьер → брокер
(`booking_confirmed` не годится: его публикует воркер напрямую).

## Модуль «A/B-эксперименты „Суфлёра“»

Флаг с вариантами (`variants`, кумулятивные доли, сумма ≤ 100) становится
экспериментом: тот же детерминированный бакетинг распределяет сущности

## Модуль «Реферальная программа»

Приглашение по коду: регистрация с `?ref=CODE` привязывает `referred_by`
один раз и навсегда, первая оплаченная бронь друга награждает обе стороны
(300 пригласившему, 100 welcome другу) в транзакции вердикта воркера —
атомарный захват метки `UPDATE … RETURNING` гасит гонку двух оплат и
ределивери. Отмена награждённой брони сжигает награды clawback'ом (не в
минус), повторного начисления не будет.
