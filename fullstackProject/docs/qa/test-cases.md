# Тест-кейсы: CineBooking

> **Где живут кейсы в индустрии.** Живой источник — этот md в репозитории
> (docs-as-code, ревью через PR). Снапшоты для передачи/импорта:
> [test-cases.txt](test-cases.txt) — читаемая «распечатка», как выгрузка из
> TMS; [test-cases.csv](test-cases.csv) — формат импорта в TestRail / Test IT /
> Allure TestOps (UTF-8 c BOM, открывается в Excel). В самих TMS кейсы
> хранятся в БД с прогонами и историей; Excel/Sheets — типичный вариант
> малых команд; Word — только формальные артефакты (ПМИ по ГОСТ 34).

Формат каждого кейса: идентификатор, приоритет, тип, привязка к автоматизации
(если кейс покрыт автотестом — ссылка на реальный файл в репозитории),
предусловия, шаги, ожидаемый результат, постусловия.

Приоритеты: **High** — блокирует релиз при падении; **Medium** — важная
функциональность, фикс в текущей итерации; **Low** — косметика/редкие ветки.
Типы: `функц.` / `негатив.` / `гранич.` / `конкур.` / `отказоуст.`.

Сводка: 20 кейсов, из них 14 покрыты автотестами, 6 — ручные (нужен стенд
или «глазами»).
